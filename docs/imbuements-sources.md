# Imbuements sources and behavior

Engine at `src/app/features/imbuements.js`; dataset at `src/data/imbuements.json`. Pure calculation module — no DOM, `localStorage`, or network access. Integrated into Tools → Imbuements. Recipe selection, manual material/token prices and optional estimated benefit are character-scoped inputs, restored on reload and included in full backups.

## Snapshot provenance

Checked 2026-09-17 against the independently inspected references, none of whose source code is reused here — item names, quantities, tier bonus text, fee and token-count figures are treated as game facts, independently re-implemented.

- **[Official Tibia news, 2025-06-12](https://www.tibia.com/news/?id=8396&subtopic=newsarchive)** — primary and authoritative source that the imbuing success-chance boost mechanic was removed: every imbuement tier is now 100% success, at fixed per-tier fees of **7500gp (Basic)**, **60000gp (Intricate)** and **250000gp (Powerful)**, across **24** imbuement types. This is a patch to the game itself, not a source disagreement — it supersedes both community repos' pre-patch fee figures below, and confirms TibiaPal's 60000gp Intricate figure was correct all along (exiva-xp's 55000gp was simply pre-patch).
- **[TibiaWiki: Punch](https://tibia.fandom.com/wiki/Punch)** — primary for the newly added Punch imbuement (Fist Fighting): Basic +1 Fist Fighting (25 Tarantula Egg), Intricate +2 (adds 20 Mantassin Tail), Powerful +4 (adds 15 Gold-Brocaded Cloth), and that Punch does not support gold-token exchange.
- **[TibiaWiki: Imbuing](https://tibia.fandom.com/wiki/Imbuing)** — corroborates the current 24-imbuement-type catalog (23 pre-existing types plus Punch) and general imbuing mechanics.
- **[TibiaWiki: Powerful Strike](https://tibia.fandom.com/wiki/Powerful_Strike)** — its notes date the game balance change to **2025-07-21** with critical stats changing from 10% chance / 50% damage to **5% chance / 40% damage**, matching exiva-xp's figure below. This resolves the Strike disagreement this dataset previously flagged as unresolved (see "Two disagreements this module used to flag" below); `imbuements[strike].tiers.powerful` no longer carries an `uncertain` note.
- **[nesleykent/exiva-xp](https://github.com/nesleykent/exiva-xp) revision [`1d65728c7`](https://github.com/nesleykent/exiva-xp/blob/1d65728c7f3a720972d5b8c6be7085c6ca32c9bf/assets/js/engine/imbuements.js)** — source for the 23 pre-existing imbuements' item lists, quantities, tier bonus text and the `supportsGoldTokenExchange` flag. That file's own header states it was checked directly against each tier's TibiaWiki `{{Infobox Imbuement}}` template on 2026-07-06. Treated here as curated factual evidence, not as code to copy. ## Two disagreements this module used to flag — now resolved

Both were previously recorded in `imbuements.json`'s `source.uncertainties` and surfaced via `listFlaggedImbuements()`. Primary-source verification has since resolved both; they now live in `source.resolvedUncertainties` for history, and `listFlaggedImbuements()` returns an empty list.

1. **Intricate guaranteed-success fee.** exiva-xp's `IMBUING_FEES.intricate` was `55000`; TibiaPal's `calculate_intricate_imbue` used `60000`. The 2025-06-12 official patch note confirms `60000` was correct, and further changes it (post-patch) alongside Basic dropping from `15000` to `7500`; Powerful stays `250000`.
2. **Powerful Strike's damage/chance bonus.** exiva-xp stated `+40% damage (5% chance)`; the tibiawiki-sql fixture's effect template call implied `+50% damage (10% chance)`. TibiaWiki's own Powerful Strike page was corrected on 2025-07-21 to `5% chance / 40% damage`, matching exiva-xp — the fixture had simply captured a stale pre-correction revision.

## Remaining unresolved uncertainties

Recorded in `imbuements.json`'s `source.uncertainties`:

- Neither the official 2025-06-12 patch note nor the TibiaWiki Imbuing/Punch pages restate the `2/4/6` gold-token quantities per tier; those figures are carried over unverified from the pre-patch exiva-xp/TibiaPal community sources.
- Gold-token exchange support itself (confirmed only for Vampirism, Void and Strike, and explicitly absent for Punch per its TibiaWiki page) is likewise carried over from the pre-patch sources; the official note addresses fees and success chance only, not token exchange.

## What is — and is not — modeled

- **Success chance.** Per the 2025-06-12 official patch, imbuing no longer has a success-chance boost mechanic: every tier of every imbuement is always 100% success at the fixed fee. There is no lower-cost, lower-certainty fee option in this dataset or the game itself; `calculateTier`'s results always assume 100% success.
- **Fee model.** `TIER_FEES` is `{basic: 7500, intricate: 60000, powerful: 250000}`, the fixed per-tier installation fee from the 2025-06-12 official patch note. This is not a "guaranteed-success surcharge" on top of some base fee — per that patch, it is simply the whole fee, since every imbuement is always 100% success.
- **Active duration and cost/hour.** `ACTIVE_DURATION_HOURS` is `20`, from TibiaPal's `/20` per-hour figure (unaffected by the 2025-06-12 fee patch). `costPerActiveHour(total, activeHours = 20)` divides any known total by this figure; every acquisition option in `calculateTier`'s output carries its own `costPerHour`.
- **Gold-token substitution.** Only Vampirism, Void and Strike carry `supportsGoldTokenExchange: true` — the only three types both TibiaPal's UI and exiva-xp's per-imbuement flag corroborate; Punch's TibiaWiki page explicitly confirms it does not support token exchange. Whether other imbuement types accept token exchange in the current game version is not established by these references and is not assumed. `getAcquisitionOptions` returns, for a supported imbuement and target tier: a market-only option, a fully-token option, and one hybrid option per lower tier (buy that lower tier's package with tokens, then only the market materials the remaining tiers *add* — never double-counting a lower tier's materials). `selectCheapestOption` picks the lowest complete (`total !== null`) option.
- **Recipes are stored incrementally, not cumulatively.** `imbuements.json` records each tier's `addedMaterials` — what that tier alone adds beyond the previous one, matching what an NPC actually sells for that upgrade. `getIncrementalMaterials` returns that list as-is; `getCumulativeMaterials` merges every tier up to and including the requested one (summing quantities for any item id repeated across tiers, defensively — none of the 24 bundled recipes actually repeat an item across their own tiers, but hybrid-option math and any future dataset entry rely on the merge being correct regardless). Punch's recipe is cumulative like every other type: its Powerful tier requires all of Tarantula Egg, Mantassin Tail and Gold-Brocaded Cloth from scratch.
- **Manual prices, never a guessed one.** `prices` is a plain `{ itemId: number }` map the caller supplies (e.g. from Bestie's Market Watch feature, when available) or leaves incomplete. A price resolves to *unknown* only when it is absent, `null`, or `undefined`. **An explicit `0` is a legitimately known price** — e.g. a material the player already owns or farms for free — and is priced as zero cost, not treated as missing. A negative or non-finite (`NaN`/`Infinity`) price is a caller error and throws immediately, since that is malformed input rather than a legitimate unknown or a free material. Any option with at least one unknown price used in it reports `total: null` and lists every missing item name in `missingItems`; it is never estimated.
- **Custom recipes.** `priceCustomRecipe({ materials, fee, prices })` prices an arbitrary material list (name + positive integer quantity + optional fee) against the same price convention, for materials or whole recipes this catalog does not cover.
- **Break-even is opt-in and never guaranteed.** `evaluateBreakEven({ totalCost, activeHours, observedBenefitPerHour })` only computes a net/break-even projection when the caller supplies `observedBenefitPerHour` — a player's own estimate of the imbuement's hourly value (extra loot, survivability, etc.), not a value this module measures or asserts. The result always carries `guaranteed: false`; omitting the benefit returns only the cost side (`costPerHour`), with everything else `null`.

## Tests

`tests/imbuements.test.js` independently re-derives a handful of costs by hand (not by re-running the engine's own arithmetic) and covers: incremental vs. cumulative material counts and quantities agreeing at every tier; every recipe count present at the expected 24 imbuements (including Punch) and 3-per-imbuements token-supported subset; the fixed 7500/60000/250000 fees and empty `listFlaggedImbuements()` now that Strike is resolved; Punch's own cumulative recipe and lack of token support; token/hybrid option coverage and that hybrids never double-count a lower tier's materials; a missing (absent/`null`/`undefined`) price leaving totals `null`, an explicit `0` price pricing as free, and a negative/non-finite price being rejected; the fixed fee and 20-hour cost/hour figures; break-even with and without a supplied benefit; and the custom-recipe helper's own validation.
